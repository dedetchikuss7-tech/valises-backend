# LOT #264 — Context Engineering Foundation

> Status: IN_PROGRESS
> Branch: `feature/264a-context-engineering`
> Author: Deniol Tchikoua
> Date: 2026-05-23

## Goal

Establish a persistent, structured context layer (`project-context/`) that gives any new conversation — human or AI — an accurate, up-to-date picture of the project without requiring repeated codebase exploration. This foundation prevents context drift, documents key decisions and traps, and provides templates for future lots.

## Scope

### In scope
- `project-context/CURRENT_STATUS.md` — current state, what works, what doesn't, lot history
- `project-context/ARCHITECTURE.md` — module map, data model, auth model, provider pattern, state machine
- `project-context/DECISIONS.md` — 14 key architectural decisions with rationale (D-001 to D-014)
- `project-context/KNOWN_TRAPS.md` — 14 known pitfalls with fixes (T-001 to T-014)
- `project-context/LOT_TEMPLATE.md` — standardized template for future lot documentation
- `project-context/lots/LOT_264.md` — this file

### Out of scope
- Implementation of any feature
- Changes to `src/` code
- Changes to `prisma/schema.prisma`
- CI pipeline changes

## Context

This lot has no code predecessors in the usual sense. It is a meta-lot: its output is the context system that future lots will depend on.

The project reached production-architecture maturity around Lot #263 (security hardening, CORS, production seeds). At this point, the codebase has 30+ Prisma models, 40+ NestJS modules, and ~14 lots of accumulated decisions. Without a context layer, each new session requires 30–60 minutes of re-exploration.

Key references:
- Recent lots: #261 (webhooks/Sentry/JWT), #262 (commission/payout), #263 (seeds/CORS/security)
- `src/app.module.ts` — registered modules
- `prisma/schema.prisma` — data model (source of truth)

## Approach

### Files created

| File | Purpose |
|---|---|
| `project-context/CURRENT_STATUS.md` | Living document: what works, what's in progress, key invariants, how to run |
| `project-context/ARCHITECTURE.md` | Module map, data model, auth flow, provider pattern, state machine diagram |
| `project-context/DECISIONS.md` | D-001 to D-014: decisions with rationale and implications |
| `project-context/KNOWN_TRAPS.md` | T-001 to T-014: pitfalls with fixes and cross-references |
| `project-context/LOT_TEMPLATE.md` | Template for future lot specs |
| `project-context/lots/LOT_264.md` | This file |

### Maintenance protocol

After each completed lot:
1. Update `CURRENT_STATUS.md` — add the lot to history, update "What is in progress"
2. Add new decisions to `DECISIONS.md` (D-NNN format)
3. Add new traps discovered during the lot to `KNOWN_TRAPS.md` (T-NNN format)
4. Create `lots/LOT_NNN.md` before starting the lot (not after)
