## Context

Backend is production-ready since Lot #263. The mobile contract (`/mobile/me/contract`) is the central data contract for FlutterFlow. A gap was identified: the corridor `id` (UUID) was not exposed in the mobile contract response, making it impossible for clients to create trips or packages (both `POST /trips` and `POST /packages` require `corridorId` UUID). This was fixed as part of this lot.

Key references:
- `src/mobile-contract/mobile-contract.service.ts` — mobile contract service
- `src/main.ts` — CORS configuration (exact-match, no wildcard support)
- `project-context/ARCHITECTURE.md` — module map

## What was done

### Fix: Mobile contract now exposes corridor UUID

The `getMyContract` response now includes `corridors[].id` (UUID) in addition to `code`, `name`, and `status`. This UUID is required as `corridorId` when calling:
- `POST /trips`
- `POST /packages`

Without this fix, FlutterFlow clients had no way to obtain the corridor UUID from the API.

**Change:** `src/mobile-contract/mobile-contract.service.ts` — added `id: true` to the Prisma `select` for `corridor.findMany`.

### Script: validate-mobile-endpoints.sh

Tests all 20 MVP endpoints in sequence. The script:
- Registers a fresh test user (timestamp-based email to avoid conflicts)
- Authenticates and extracts JWT
- Extracts `corridorId` from `GET /mobile/me/contract`
- Creates a trip, package, declares content, publishes the package
- Tests matching, transactions, legal acknowledgements, notifications, activity feed
- Displays ✅ / ❌ per endpoint and a final score X/20

**Score target:** ≥ 18/20. Endpoints 13, 15, 16, 18 (transaction-related) require an `ACTIVE_TRIP_ID` env var pointing to a trip whose ticket has been admin-verified. Without it, score ≈ 16/20.

**To achieve 18+/20:**
```bash
ACTIVE_TRIP_ID=<uuid-of-admin-verified-trip> bash scripts/validate-mobile-endpoints.sh
```

### CORS analysis

The current CORS implementation (`src/main.ts`) uses `allowedOrigins.includes(origin)` — exact string matching. FlutterFlow web apps hosted on `*.flutterflow.app` or `*.web.app` require their specific domain to be added to the `CORS_ORIGINS` Railway env variable. This is documented in the guide. **No code change is needed** — the existing env-var-driven CORS is sufficient; the customer just needs to set their URL.

## Notes

- Mobile app clients (iOS/Android) are not affected by CORS — they only need the JWT.
- The corridor UUID gap was a silent API design issue: the API accepted UUIDs in request bodies but never exposed them in any list response. Fixed in this lot.
- For the transaction-related tests (13, 15, 16, 18) to pass, the test environment must have a trip that went through the full admin ticket-verification flow. This is a one-time setup task for the test environment.
- The script exits with code 0 if ≥ 18/20, code 1 otherwise. This makes it CI-friendly.
